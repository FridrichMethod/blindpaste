# blindpaste 设计文档

日期：2026-08-10
状态：已批准，待实现

## 问题

别人要发我一串数字（密码 / 一次性口令）。我不想让它出现在我的屏幕上，但需要它进入 macOS 剪贴板，以便直接 `Cmd-V` 粘贴。

关键判断：**`pbcopy` 只是后半段，真正的约束在传输通道。** 只要对方把数字当普通文本发到微信或邮件里，它在我打开对话的那一刻就已经渲染到屏幕上了，任何剪贴板技巧都救不回来。因此明文必须在到达我眼睛之前就被包住 —— 对方发送的必须是不可读的编码或密文。

## 已确认的前提

- 发送方能在自己终端里跑一条命令（这排除了依赖一次性密文网站的方案）。
- 本机 `/Applications`、`~/Applications`、Setapp 目录及运行中进程均无剪贴板管理器（Raycast / Alfred / Maccy / Paste / Clipy / Flycut 都没有）。
- 本机 `age` 与 `bats` 均未安装；`base64`、`pbcopy`、`pbpaste`、`shasum`、`nohup` 可用。
- 本机 `base64` 是 BSD 风格，解码用 `-D`（GNU 的 `-d` 不可用）。

## 方案

一个 bash 脚本 `blindpaste`。把剪贴板里的密文原地替换为明文；明文全程只存在于管道和 shell 变量中，屏幕上只显示长度和字符类别这样的元信息。

### 双格式，自动嗅探

发送方能跑命令行不等于装了 `age`，所以脚本嗅探输入内容：

| 格式 | 判据 | 性质 |
| --- | --- | --- |
| `age` ASCII armor | 含 `BEGIN AGE ENCRYPTED FILE` | 真加密。聊天记录泄露也安全。长期首选 |
| base64 | 去掉空白后匹配 `^[A-Za-z0-9+/]+={0,2}$` | 仅遮蔽，非加密。零安装，day-1 可用 |
| 其它 | — | 报错退出，剪贴板保持原样 |

嗅探让发送方从 base64 升级到 age 时，接收端零改动。

base64 只是遮蔽而非加密，这一点必须写进 README：它满足「我不想看到」，但不满足「聊天服务商不该拿到」。要后者就必须装 `age`。

### 命令接口

| 命令 | 行为 |
| --- | --- |
| `blindpaste` | 主路径。读剪贴板 → 嗅探 → 解码 → 写回剪贴板 |
| `blindpaste -` | 同上，但密文从 stdin 读 |
| `blindpaste --sender` | 打印转发给对方的命令。**始终同时打印两条**：base64 版本，以及 age 版本（仅当已 `--init`）。我按对方是否装了 `age` 自行取用 |
| `blindpaste --init` | 生成 age keypair 到脚本所在目录的 `.blindpaste.key`，`chmod 600`，打印公钥。可用 `BLINDPASTE_KEY` 覆盖路径 |
| `-t <秒>` | 覆盖自动清空 TTL，默认 90，`-t 0` 关闭 |
| `blindpaste --__clear <hash>` | 内部用，由后台进程调用。见「自动清空」节 |

`--sender` 同时打印两条而非二选一：我这边有没有 age 密钥和对方那边有没有装 `age` 是两件独立的事，脚本无法知道后者，所以由我在转发时决定。

### 给发送方的命令

`--sender` 输出的命令有两个必需性质：**不把明文写进对方的 shell history**，且**不依赖 `pbcopy`**（对方可能在 Linux 或 WSL）。密文本身不是秘密 —— 对方本来就知道明文 —— 所以直接打到他的终端里，由他自己复制，比塞进他的剪贴板更通用。

base64 版本：

```sh
printf 'secret: ' >&2; read -rs s; printf %s "$s" | base64 | tr -d '\n'; echo; unset s
```

age 版本：

```sh
printf 'secret: ' >&2; read -rs s; printf %s "$s" | age -a -r <我的公钥>; unset s
```

`read -rs` 让对方屏幕上也不回显；`tr -d '\n'` 抹掉 BSD `base64` 对长输入的换行折叠和末尾换行，保证密文是可一次选中的单行。

### 数据流

```
对方终端 read -rs ─┬─> base64 ──┐
                   └─> age -a ──┴─> 单行密文 ─> 任意聊天软件 ─> 我选中复制
                                                                    │
  ┌─────────────────────────────────────────────────────────────────┘
  v
pbpaste ─> 嗅探 ─┬─> base64 -D ─┬─> $plain（仅内存）─┬─> pbcopy
                 └─> age -d ────┘                   ├─> 元信息 ─> stderr
                                                    └─> shasum ─> 后台守卫
```

`$plain` 只经由管道流动。它绝不出现在 stdout、stderr、argv、任何文件或任何命令行参数中。

### 成功输出

```
✓ age  →  剪贴板已就绪（6 字符，全数字）
  90 秒后自动清空（仅在剪贴板未被改动时）
```

这一行是整个设计成立的前提。我看不到内容，所以必须能确认解码成功且位数符合预期 —— 否则盲粘贴一个坏结果时我完全无法判断发生了什么。输出走 stderr，这样 `blindpaste` 可以出现在管道里而不污染 stdout。

元信息只包含：格式、字符长度（`${#plain}`）、字符类别。字符类别按以下优先级取**第一个**匹配项，互斥单值：含非字母数字字符 → `含符号`；含字母 → `含字母`；否则 → `全数字`。不含明文的任何字节。

### 自动清空，带 hash 守卫

后台进程用 `nohup "$0" --__clear "$h" -t "$ttl" &` 加 `disown` 启动，而非 `nohup bash -c '<内联脚本>'`。两个原因：避免把 hash 拼进嵌套引号的字符串里，以及让清空逻辑成为可被测试直接调用的同一份代码。关闭终端时 SIGHUP 会杀掉后台进程，`nohup` 是必需的，否则剪贴板会永远留着明文。

`--__clear` 的行为：`sleep $ttl`，然后重新计算当前剪贴板内容的 SHA-256 前 16 位，与传入的 hash 比对，**不一致则什么都不做**。这避免了「90 秒后把我后来复制的东西删掉」这个 bug。传给后台进程的是 hash 而非明文，且 hash 是纯十六进制，无注入风险。

两处 hash 必须以相同方式计算：写入时对 shell 变量 `$plain` 求值，检查时对 `$(pbpaste)` 求值。两者都已被命令替换剥掉尾部换行，因此一致。

### 错误处理

所有失败路径都保持剪贴板原样，且不打印解码结果的任何字节（部分解码也可能泄露）。

| 退出码 | 条件 | 消息要点 |
| --- | --- | --- |
| 0 | 成功 | 元信息 |
| 1 | 用法错误 | 未知 flag、`-t` 缺参数或非整数、`--init` 时密钥已存在 |
| 2 | 嗅探失败 | 两种格式都不匹配，剪贴板未改动 |
| 3 | 缺依赖 | 是 age 密文但 `age` 未安装 → 提示 `brew install age` |
| 4 | 解码失败 | base64 损坏，或 age 私钥不匹配 |
| 5 | 输入为空 | 剪贴板为空 |

`age -d` 仅在成功时向 stdout 写明文，失败时非零退出。实现上用 `plain=$(... 2>/dev/null)` 并检查退出码，退出码非零时绝不使用 `$plain` 的内容。

`--init` 在密钥文件已存在时必须拒绝覆盖并非零退出。

## 明确不做

- **`org.nspasteboard.ConcealedType` 标记。** 这是让剪贴板管理器跳过记录的社区约定，但 `pbcopy` 和 AppleScript 都设不了，需要 Swift 或 pyobjc。本机已确认无剪贴板管理器，故不做，仅记入 README 限制章节。以后装了 Raycast/Alfred/Maccy 必须补上，否则「不被我看到」失效 —— 明文会进管理器历史。
- **通用剪贴板（Handoff）处理。** 剪贴板会同步到 iPhone/iPad。关闭 Handoff 是系统设置里的操作，不是代码职责。README 提示。
- **`age -p` 口令模式。** 还需另开渠道传口令，比一次性交换公钥更麻烦。
- **二进制或含 NUL 的密文。** shell 变量无法承载 NUL。本工具面向文本密码。README 说明。

## 已知限制

- 明文尾部的空白字符会被命令替换剥掉。对数字口令是正确行为，但不适用于「尾部空格有意义」的密文。
- 明文在剪贴板中期间，同机任何进程都能读取它。这是 macOS 剪贴板的固有性质，本工具只能缩短暴露窗口，不能消除它。
- 若在 TTL 到期前关机或杀掉后台进程，剪贴板不会被清空。

## 文件结构

```
blindpaste            # 主脚本，bash，约 100 行
tests/run.sh          # 自带测试，零安装
README.md             # 用法 + 限制章节
```

仓库自包含：不安装到 `~/.local/bin` 或任何系统位置，直接从仓库目录跑 `./blindpaste`。

自包含的推论是密钥必须留在仓库内（`.blindpaste.key`），因此：`.gitignore` 必须显式列出它；密钥路径必须由 `BASH_SOURCE` 推导而非 `$0`（否则 `BLINDPASTE_LIB=1` 被 source 时算错目录）；`init_key` 只在目录不存在时才 `mkdir` + `chmod 700`，因为默认目录就是仓库根目录，对已存在的目录 `chmod 700` 会改掉仓库自身权限。测试必须断言这些属性，包括用 `git check-ignore` 验证密钥被忽略。

代价是仓库里躺着一个私钥。这是用自包含换来的，README 必须明确警告推远端前先确认。

## 测试

不用 bats（未安装，且为 100 行脚本引入两个 brew 依赖不划算）。`tests/run.sh` 是自带的 shell 测试器。

脚本支持 `BLINDPASTE_LIB=1` 环境变量：设置时只定义函数、不执行主流程，使测试能直接调用 `sniff` 等纯函数，无需为测试暴露公开 flag。

覆盖点：

1. base64 往返：已知明文 → 编码 → `blindpaste` → 剪贴板内容逐字节等于原明文。
2. age 往返：同上（若 `age` 未安装则跳过并明确报告为 skip，不静默通过）。
3. 嗅探三分支：age armor、合法 base64、垃圾输入。
4. 垃圾输入不污染剪贴板：预置已知内容 → 喂垃圾 → 断言剪贴板未变且退出码为 2。
5. hash 守卫，两个方向都要测：(a) 写入 → 手动改剪贴板 → 直接调 `--__clear <旧hash> -t 0` → 断言新内容未被删；(b) 写入 → 不动剪贴板 → 调 `--__clear <正确hash> -t 0` → 断言剪贴板已清空。只测 (a) 会让一个永不清空的实现也通过。
6. 明文不泄露：捕获 stdout 与 stderr，断言其中不含明文子串。
7. 缺依赖路径：伪造 age 密文且 `PATH` 中屏蔽 `age` → 断言退出码 3。

测试会读写真实剪贴板。`tests/run.sh` 必须在开始时保存原剪贴板内容、结束时恢复，并全程用 `-t 0` 以免后台清空进程干扰断言。测试不可并行运行。

对一个 100 行的 shell 工具，这些是有意义的测试层。不会为了凑单元测试比例去人为拆分函数。
