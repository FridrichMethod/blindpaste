# blindpaste

[English](README.md) | **简体中文**

别人给你发一串密码或一次性口令。你不想让它出现在自己的屏幕上，但需要它进剪贴板，好直接 `Cmd-V`。

`blindpaste` 把 macOS 剪贴板里的密文原地替换为明文。明文只经由管道进 `pbcopy`，屏幕上只显示长度和字符类别：

```
$ ./blindpaste
ok  b64 -> clipboard ready (6 chars, digits only)
    auto-clear in 90s (only if the clipboard is still unchanged)
```

这一行元信息是整个设计成立的前提。你看不到内容，所以必须能确认解码成功、位数符合预期，否则盲粘贴了一个坏结果也无从判断。

> [!WARNING]
> **剪贴板管理器会让这个工具失效。** 只要 Raycast、Alfred、Maccy、Paste 或任何剪贴板历史工具在运行，明文*一定*会进它们的历史记录，下次翻历史就会看到。如果你的剪贴板管理器支持忽略指定应用，把终端加进去；否则不要和它同时使用 blindpaste。详见[限制](#限制)。

## 环境要求

- **你（接收方）：** macOS。系统自带的 `/bin/bash`（3.2）就够用。可选：[`age`](https://github.com/FiloSottile/age)，用于真加密（`brew install age`）。
- **发送方：** 任意 bash 或 zsh，macOS、Linux、WSL 都行。用 base64 什么都不用装；用加密版本需要 `age`。

## 关键点：剪贴板只是后半段

只要对方把数字当普通文本发到微信或邮件里，它在你打开对话的那一刻就已经渲染到屏幕上了，任何剪贴板技巧都救不回来。**明文必须在到达你眼睛之前就被包住** —— 对方发送的必须是不可读的编码或密文。

所以用法的第一步是把命令发给对方：

```sh
./blindpaste --sender
```

它打印出对方该跑的命令。这些命令有两个性质：不把明文写进对方的 shell history（用 `IFS= read -rs` 读取），也不依赖 `pbcopy`（对方可能在 Linux 或 WSL）。密文不需要对对方保密 —— 对方本来就知道明文 —— 所以直接打印在对方终端里，由对方复制转发即可。

对方把输出的那串乱码发给你。你选中复制，跑 `./blindpaste`，然后 `Cmd-V`。

## 两种格式的安全性不同

| 格式 | 对方需要 | 性质 |
| --- | --- | --- |
| base64 | 什么都不用装 | **只是遮蔽，不是加密。** 挡住你的眼睛，挡不住聊天服务商 —— 对他们来说密文和明文等价 |
| age | 装好 `age` | 真加密。聊天记录泄露也安全 |

脚本会自动嗅探收到的是哪种，不需要告诉它。

**如果这串字符是长期有效的真密码，而不是几分钟就失效的一次性口令，就该用 age。** base64 只适合「一次性口令，而我只是不想看到它」这种场景。

启用 age：

```sh
brew install age
./blindpaste --init          # 在仓库根目录生成 .blindpaste.key，权限 600
./blindpaste --sender        # 现在会同时打印 age 版本的命令
```

`--sender` 始终打印 base64 版本，有密钥时再追加 age 版本。*你*这边有没有密钥、和*对方*那边有没有装 `age`，是两件独立的事，脚本无法知道后者，所以由你在转发时决定发哪条。

## 用法

```
./blindpaste [-t 秒]     读剪贴板里的密文，解码后写回剪贴板
./blindpaste - [-t 秒]   密文改从 stdin 读
./blindpaste --sender    打印转发给对方的命令
./blindpaste --init      生成 age keypair
-t 0                     不自动清空剪贴板（默认 90 秒后清空）
```

退出码：`0` 成功、`1` 用法错误（包括密钥已存在时再跑 `--init`）、`2` 无法识别格式、`3` 缺依赖（没装 `age`、私钥不可读，或不在 macOS 上）、`4` 解码失败、`5` 输入为空。**所有失败路径都保持剪贴板原样**，且不打印解码结果的任何字节。

## 自动清空带 hash 守卫

默认 90 秒后清空剪贴板，但清空前会重新比对剪贴板内容的 hash：**如果你在这期间复制了别的东西，就什么都不做。** 否则这个功能会变成「90 秒后把你刚复制的东西删掉」。

负责清空的是一个忽略 SIGHUP 的后台子 shell，所以关掉终端也杀不掉它。用来比对的 hash 只存在于这个进程的内存里，绝不出现在命令行参数中：`ps` 能让本机所有用户看到每个进程的参数，终端安全 / 审计软件也常常记录它们；而对 6 位数字口令来说，hash 和明文等价（穷举全部 10^6 种可能不到一秒）。守卫是「失败即不动」的：如果算不出 hash（没有 `shasum`），就关闭自动清空并给出警告，而不是冒险清掉别的内容。

## 自包含

不需要安装，从仓库目录直接跑 `./blindpaste` 就行。

这个工具不往 `$HOME`、`/usr/local`、shell 配置或任何系统位置写东西。age 私钥也生成在仓库根目录（`.blindpaste.key`），而不是 `~/.config`。`tests/run.sh` 用断言锁住了这个属性：默认密钥路径必须在仓库内（通过符号链接运行时也一样），必须被 `.gitignore` 覆盖，代码里不许出现 `$HOME` 或 `.local/bin`。

代价是**仓库里躺着一个私钥**。`.gitignore` 明确列了 `.blindpaste.key`，测试也会用 `git check-ignore` 验证，但是：

- 把你的这份仓库推到任何远端之前，先自己确认一遍。
- `git clean -fdx`（或 `-fdX`）会删除被忽略的文件 —— **包括你的私钥**。删掉了就重新 `--init`，再把新的 `--sender` 命令转发给对方。用旧密钥加密的密文从此无法解密，对一次性口令来说无所谓。
- 如果仓库放在同步目录里（iCloud Drive、Dropbox 等），私钥也会被同步。

想把密钥放到别处，用环境变量覆盖：

```sh
BLINDPASTE_KEY=~/somewhere/else.key ./blindpaste
```

嫌每次打 `./` 麻烦，可以自己加 alias 或符号链接（工具不会替你改任何 shell 配置）：

```sh
alias blindpaste="$PWD/blindpaste"
# 或者
ln -s "$PWD/blindpaste" ~/bin/blindpaste
```

符号链接会被解析，所以无论哪种方式，默认密钥都仍在仓库根目录。

## 测试

```sh
./tests/run.sh
```

不依赖 bats，仅支持 macOS。测试会读写真实剪贴板：开始时保存文本内容、结束时恢复（图片等非文本内容不会恢复），所以**不可并行运行**。`age` 未安装时，相关测试报 skip 而不是静默通过。跑一遍要几秒钟，因为要等一次真实的自动清空触发。

## 限制

以下三条决定「不会出现在我屏幕上」是否真的成立，值得逐条读：

1. **没有设 `org.nspasteboard.ConcealedType`。** 这是让剪贴板管理器跳过记录的社区约定，但 `pbcopy` 和 AppleScript 都设不了，需要 Swift 或 pyobjc。**装了 Raycast / Alfred / Maccy / Paste，明文就会进它们的历史记录，翻历史时你一定会看到。**
2. **通用剪贴板（Handoff）会把剪贴板同步到 iPhone / iPad。** 要挡住，得在系统设置里关掉 Handoff。那是系统配置，不是本工具的职责。
3. **明文在剪贴板里的这段时间，你登录会话里的任何应用或进程都能读它。** 这是 macOS 剪贴板的固有性质。本工具只能缩短暴露窗口，不能消除它。

其它：

- 明文尾部的空白字符会被剥掉（shell 命令替换的固有行为）。对数字口令是正确行为。
- 明文必须是单行可打印 ASCII（字节 0x20–0x7E）。非 ASCII 的密码（中日韩文字、带重音的字母、emoji）和多行密码会以退出码 4 被拒绝。这正是最后一条描述的安全网。
- 不支持二进制的密码 —— shell 变量承载不了 NUL 字节，所以解码结果含 NUL 时会以退出码 4 被拒绝。本工具面向文本密码。
- 若在 TTL 到期前关机或杀掉后台进程，剪贴板不会被清空。
- 格式嗅探无法区分真正的 base64 和一串恰好长度合法的纯数字或纯字母。脚本用「解码结果必须是可打印 ASCII」作为安全网，把这种情况变成退出码 4，而不是往剪贴板塞垃圾字节。这个网不是百分之百的：解码出的垃圾恰好全是可打印 ASCII 时会漏过，但这时元信息行里的字符类别会显示 `has symbols`，足以让你察觉不对。
